04校验与变更：提交什么，不提交什么

validate()

清空字段错误与表单错误
contact ← 输入内容去除首尾空白
contact 为空 → 内容错误
tag 不在 TAG 枚举 → 分类错误
编辑模式下 status 不在 STATUS 枚举 → 状态错误
返回是否全部通过

校验失败：
    按 内容 → 分类 → 状态 的顺序
    聚焦第一个错误字段，停止提交

buildPatch()

changes ← 空对象
若 trim(内容) ≠ trim(初始内容)：
    changes.contact ← trim(内容)
若分类 ≠ 初始分类：
    changes.tag ← 当前分类
若状态 ≠ 初始状态：
    changes.status ← 当前状态
返回 changes
例如只把 CREATE 改成 DONE，PATCH 正文只有 {"status":"DONE"}。只改变内容首尾空白不算变更。编辑器负责比较新旧值，API 层再做可发送字段过滤。

关闭前的 hasChange()

新建模式：内容 trim 后非空，或分类与初始分类不同 → 有改动
编辑模式：内容 trim 后、分类、状态任意一项不同 → 有改动

无改动的编辑仍先经过校验；通过后直接关闭，并回调 unchanged: true，不写入、不刷新、不显示成功提示。

05提交：写入完成后，等待刷新

handleSubmit(event)：
    阻止表单默认提交
    若 submitting → 忽略重复提交
    若 validate 失败 → 聚焦错误字段，结束

    编辑模式：
        changes ← buildPatch()
        若为空：关闭，回调 unchanged，结束
        锁定表单
        等待 Store.update(item.ID, changes)
    新建模式：
        锁定表单
        等待 Store.create({ contact: trim(内容), tag, status: CREATE })

    成功 → 关闭弹窗 → onSaved(结果, mode)
    失败 → 解锁表单 → 展示错误并聚焦
锁定表单保存、取消、删除禁用
内容只读，选择器禁用
→
POST / PATCH写入后端
→
refresh()沿用当前筛选
重新获取列表
→
关闭与反馈回调 onSaved
显示成功 Toast

写入失败

Store 将写入错误抛给编辑器。弹窗保留输入，恢复按钮与控件，显示字段错误和整体错误，用户可以修改后重试。

写入成功，刷新失败

load 将刷新错误写入 state.error，不抛出。因此 Store 仍返回写入结果，编辑器关闭并显示成功提示；若当前列表仍挂载，会显示刷新错误和重试按钮。

成功提示是在 refresh 结束后触发，不是在写入响应刚返回时触发。刷新使用现有筛选，因此新建或改分类后的条目不一定出现在当前列表。

06删除：先确认，再执行写入

只在编辑模式显示「遗忘」。删除不要求当前表单校验通过，也不会保存尚未提交的内容；操作目标始终是原条目的 ID。

handleDelete()：
    若 submitting、closed 或不是编辑模式 → 结束
    submitting = true，防止重复打开确认框
    try：等待 confirmDialog(遗忘 / 留下)
    finally：submitting = false
    若编辑器已经关闭 → 结束
    若用户没有确认：聚焦删除按钮，结束

    setSubmitting(true)，禁用编辑器控件
    尝试：
        await Store.remove(item.ID)
        close() 关闭编辑器
        onDelete(item) → app 显示「已遗忘」
    失败：
        setSubmitting(false)
        showError(error)，保留编辑器供重试
点击「遗忘」
↓
等待确认结果
false ↓
留下笔记
回到编辑器，不请求删除
true ↓
DELETE /items/{ID}
成功 → refresh → 关闭 → Toast
失败 → 解锁 → 错误提示
Store.remove 等待 DELETE 后再等待 refresh。删除成功但刷新失败时，删除仍返回成功，列表通过 state.error 显示刷新失败；不会把已经成功的删除当作失败重复执行。

07确认弹窗：布尔结果只有一条出口

创建与结算

confirmDialog(options) 返回 Promise：
    settled = false，result = false
    记录当前焦点
    创建 dialog、标题、消息、取消和确认按钮
    danger 决定确认按钮的样式类
    挂载到 body，showModal()
    默认聚焦取消按钮

close(value)：
    已 settled → 不重复处理
    settled = true，result = value
    dialog.close()

收到 close 事件：
    settled = true
    移除弹窗，尝试恢复原焦点
    resolve(result)

动作与结果

用户动作返回值
点击确认按钮true
点击取消按钮false
按 Escfalse，阻止默认动作后统一关闭
点击弹窗矩形外部false
点击弹窗内部空白不关闭
未设置结果而直接关闭默认 false

背景点击先检查 event.target 是否就是 dialog，再用点击坐标与 getBoundingClientRect 判断是否在矩形外。Promise 在 close 事件中完成，不在按钮点击瞬间完成。

确认组件自身没有全局单例锁。当前编辑器在 await 期间用 submitting 阻止重复操作；showModal 使下层编辑器暂时无法交互。等待确认时没有调用 setSubmitting，因此不切换按钮文案或 disabled 状态。

08放弃修改、错误恢复与焦点

用户取消 / Esc

点击取消，或拦截编辑器的 Esc：
    requestClose()

requestClose()：
    submitting 或 closed → 结束
    若有未保存改动：
        submitting = true
        try：等待确认弹窗
            「没有记的必要」→ true
            「写下此刻的心情」→ false
        finally：submitting = false
        已关闭 → 结束
        false → 聚焦内容框，保留草稿，结束
    close()

close()：
    已关闭 → 结束
    closed = true，active = null
    dialog.close()
close 事件 → 移除编辑器，尝试恢复初始焦点

错误恢复

写入失败：
    恢复保存、取消、删除按钮
    内容恢复可编辑，选择器解除禁用
    fieldErrors 显示在对应字段
    formError 显示整体错误
    按 内容 → 分类 → 状态 聚焦错误字段

内容 input：清除内容与表单错误
分类 / 状态 change：清除对应字段错误
再次保存：重新清空旧错误并校验

无改动时，取消直接关闭。确认框中按 Esc 只取消本次放弃操作，编辑器仍然保留。

对外返回的 close() 仍是直接关闭能力，不经过确认，也不会取消进行中的写入。用户点击取消或按 Esc 才经过 requestClose。焦点恢复可能遇到原列表卡片已被刷新替换的情况。

10底层状态与请求仍如何工作

Store 状态含义
items / loading / error列表数据、请求状态、失败时的 message 与 status。
filterstag 与 status，空字符串表示全部。
order默认 ORDER.NEWEST；ORDER.OLDEST 为最早优先。
hasLoaded有效请求成功或失败后置 true；当前页面不依赖它选择渲染分支。

加载与防止旧结果覆盖

load(overrides)：
    取消旧请求，创建新控制器
    seq ← ++requestSeq
    合并 filters，设置 loading，清空 error
    请求 itemApi.list
    成功且 seq 仍有效：排序后更新 items
    主动取消 / seq 过期：忽略
    其他失败：记录 error，结束 loading

cancelLoad()：
    增加序号，使旧结果失效
    取消请求并清空控制器引用
    loading = false

状态读取与发布

subscribe(listener)：加入集合，立即通知
setState(patch)：浅合并状态，通知订阅者
getState()：返回当前状态对象本身

setFilters → 重新请求
setOrder → 复制 items，按 time 字符串排序
refresh → 沿用 filters 重新请求
create / update / remove → 写入后 refresh

getState 不是不可变快照。当前编辑入口只从中查找条目，不直接修改对象。

条目 API映射与约束
list / getGET /items，非空 tag/status 放入查询参数；GET /items/{ID}。
createPOST /items；发送 contact、tag 和可选 status，不发送 ID/time。
patchPATCH /items/{ID}；只保留 contact/tag/status 的非 null、非 undefined 值；过滤后为空则本地报 400。
removeDELETE /items/{ID}；204 返回 null，编辑模式「遗忘」按钮经确认后触发。
HTTP request：
    拼 URL，按需序列化 JSON 并设置 Content-Type
    合并外部取消信号与超时信号 → fetch
    204 / 成功空正文 → null
    成功正文 → JSON.parse
    失败响应 → 读取 detail → ApiError
        detail 数组：按 loc 汇总 fieldErrors 与 message
        detail 字符串：直接作为 message
        无可用 detail：按状态码提供默认文案
    捕获错误优先级：
        外部取消 → CanceledError
        超时 → ApiError(status = 0)
        已有 ApiError → 原样抛出
        其他 → 网络错误
    finally：清计时器与信号监听

计时器覆盖响应正文读取。写入错误原样到达编辑器，可显示 fieldErrors；列表加载仅将 message/status 保存到 state.error。

  • 弹窗与路由清理独立：编辑器和确认框位于 body 下，未纳入页面清理函数；cancelLoad 仅取消列表读取，不取消写入。
  • 编辑依据缓存：getState 返回当前共享状态对象，打开编辑器不重新查询单条数据；没有版本冲突检测。
  • 筛选继续生效：写入后 refresh 沿用当前筛选，修改分类或状态可能使条目离开当前列表。
  • 提交中共用文案：删除调用 setSubmitting(true) 时，保存按钮也会显示「保存中...」；这是当前代码的实际表现。
  • 状态只在内存：没有自动保存草稿、前端持久化、分页或独立详情页。
推荐阅读顺序：app → itemsPage → itemEditor → confirmDialog → itemStore → api/items → api/http → toast。删除与放弃修改的确认都不会直接操作后端，实际删除由编辑器在拿到 true 后触发。
