01目标与范围

第一版围绕三个动作：添加笔记 → 分类查看 → 更新内容与状态。使用一个 HTML 入口，借助 Hash 路由切换页面；界面文案与后端字段分开管理。

第一版包含

  • 主页：一个大号添加按钮、三个分类导航按钮。
  • TODOLIST、IMAGINATION、TOTAL 列表。
  • 创建、详情、编辑、状态修改、确认删除。
  • 分类和状态筛选、时间排序、加载与错误反馈。
  • 桌面、手机和键盘访问支持。

当前边界

  • 暂定 TOTAL 表示全部笔记，非统计报表。
  • 内容按纯文本展示，支持换行。
  • 不引入标题、附件、富文本和账号功能。
  • 后端暂无分页；第一版适合较小数据量。
  • 本文件描述计划，不代表功能已实现。
接口依据：后端逻辑说明。笔记内容对应 contact，标识符为大写 ID，创建时间由后端生成。

07JavaScript 伪代码

下面描述模块行为与协作关系，不是可直接运行的 JavaScript。

路由：三个列表，一套模板

ROUTES = {
  "#/":            { 页面: home },
  "#/todolist":    { 页面: items, 标题: TODOLIST, 固定分类: TODOLIST },
  "#/imagination": { 页面: items, 标题: IMAGINATION, 固定分类: IMAGINATION },
  "#/total":       { 页面: items, 标题: TOTAL, 固定分类: 无 }
}

应用启动：
    加载公共组件，监听 hashchange
    立即处理当前地址

处理路由：
    取消旧页面的列表请求，清理旧页面事件
    配置 ← ROUTES[当前 Hash]，未知地址回到主页
    若为主页：渲染大按钮与三个导航入口
    否则：渲染列表模板(配置)，加载条目

状态层：避免过期请求覆盖当前页面

列表状态 = { items: [], loading: false, error: 无, filters: {}, order: 最新优先 }
请求序号 = 0

加载列表(页面分类, 用户筛选)：
    取消上一次列表请求
    本次序号 ← 请求序号 + 1；更新请求序号
    设置 loading = true，error = 无
    查询分类 ← 页面固定分类，或 TOTAL 页面选择的分类
    尝试：
        结果 ← itemsAPI.list({ tag: 查询分类, status: 用户筛选状态 })
        若本次序号不是最新：忽略结果
        否则：按用户选择排序，更新 items
    捕获错误：
        若主动取消或请求已过期：忽略
        否则：设置可重试的错误状态
    最后：仅最新请求可以结束 loading

渲染列表状态：
    loading → 加载提示
    error → 错误说明与重试
    items 为空 → 初始空状态或筛选空状态
    否则 → 条目卡片

保存：只提交允许且实际改变的字段

保存编辑器(输入, 原条目)：
    若正在提交：返回
    内容 ← trim(输入.contact)
    校验非空内容、合法 tag 与 status
    校验失败 → 定位输入问题并返回

    若为新建：
        payload ← { contact: 内容, tag: 输入.tag, status: CREATE }
    若为编辑：
        payload ← 对比原条目，仅保留有变化的 contact / tag / status
        若 payload 为空：提示“没有修改”，不请求

    标记正在提交
    尝试 POST 或 PATCH：
        失败 → 保留输入，解释错误
        成功 → 关闭编辑器，提示已保存，再独立刷新当前列表
    解除提交锁定

渲染内容：
    使用 textContent，配合 white-space: pre-wrap
    不将笔记内容作为 innerHTML 执行

通用 HTTP 层：统一处理响应

request(method, path, body, signal)：
    URL ← API_BASE + path
    有 body 时：设置 JSON 请求头，序列化 body
    发送请求，支持主动取消与超时

    若 HTTP 状态为 204：返回 无内容
    若响应失败：
        尝试读取错误 detail，无法解析则使用通用提示
        抛出 { status, message, fieldErrors }
    否则：解析 JSON 并返回

禁止自动重试创建请求：
    超时不等于保存失败；服务器可能已经写入
    提示先检查列表，再决定是否重新提交

08API 契约与前端映射

操作后端接口成功响应
列表 / 筛选GET /items?tag=TODOLIST&status=CREATE200 · Item 数组
全部条目GET /items200 · Item 数组
详情GET /items/{ID}200 · Item
新建POST /items201 · 新 Item
局部更新PATCH /items/{ID}200 · 更新后的 Item
删除DELETE /items/{ID}204 · 无正文

创建请求示例

{
  "contact": "整理今天的实验记录",
  "tag": "TODOLIST",
  "status": "CREATE"
}

局部更新示例

{
  "status": "DONE"
}

不发送 ID / time
不发送 null 或无变化字段

数据字段

字段前端用法约束
contact内容输入、摘要、正文去除首尾空白后非空
tag分类选择、筛选、标签TODOLIST / IMAGINATION，创建必填
status状态标签、状态选择CREATE / RUNNING / DONE / CANCEL / FAILED
ID详情与更新删除的定位键后端生成，不允许前端修改
time创建时间展示与排序无时区，更新时保留原值

状态文案：CREATE → 待开始；RUNNING → 进行中；DONE → 已完成；CANCEL → 已取消；FAILED → 未完成。后端未规定状态转换顺序。

时间与排序：后端按 time 字符串升序返回，前端默认最新优先。时间按后端原值表达，不擅自转换成 UTC，不显示为“更新时间”；异常格式保留原文或显示“时间未知”，避免错误日期。

错误到界面的映射

情况前端处理
400 · 空 PATCH前端以变更比较避免发出；收到后提示没有可保存的修改。
422 · 校验失败提示具体字段；PATCH 不允许额外字段或显式 null。
404 · 条目不存在提示条目已不存在，关闭失效详情并刷新列表；有未保存输入则保留供复制。
网络 / 服务器错误展示可理解的错误与重试入口，保留编辑内容。
主动取消旧列表请求不展示错误，等待当前有效请求。

查询参数目前是普通字符串，非法筛选值可能返回空数组，因此 UI 只提供合法枚举；“全部”对应省略参数。现有接口没有分页，分页不能仅靠添加查询参数获得。

09访问配置、实现顺序与验收

建议采用同源访问

页面路径

浏览器访问 /，由静态服务器提供 frontend/index.html 和资源。

Hash 中的页面路径在浏览器内部处理。

接口路径

前端请求 /api/items，代理去掉 /api 前缀，转发至 FastAPI /items。

config.js 中设置 API_BASE 为 /api。

这是拟采用的配置。后端当前根路径返回基础 JSON；文档未说明已配置静态托管、代理或 CORS。实施时需要补充访问配置；若采用不同源开发，则需明确配置允许的前端来源。

实现顺序

1 · 页面骨架路由、样式、响应式布局
→
2 · 读取接口列表、详情、筛选、错误
→
3 · 写入交互创建、编辑、状态、删除
→
4 · 联调验收访问配置、边界与可访问性

完成标准

  • 打开网站首先显示主页大按钮和三个导航入口；刷新与浏览器前进后退正常。
  • 两种分类列表与 TOTAL 内容正确；分类、状态筛选和时间排序一致。
  • 空白内容无法提交；创建后能查到记录；编辑不改变 ID 和创建时间。
  • PATCH 仅发送变更字段；删除成功后无 JSON 解析错误；取消删除不会发请求。
  • 快速切换页面时无旧结果覆盖；失败保留输入；保存成功与刷新失败分别提示。
  • 空列表、筛选无结果、404、422 和网络失败均有对应反馈。
  • 手机不横向溢出；键盘可以完成添加和关闭弹窗；长文本与换行正常展示。
