04校验与变更：提交什么，不提交什么

validate()

清空字段错误与表单错误
contact ← 输入内容去除首尾空白
contact 为空 → 内容错误
tag 不在 TAG 枚举 → 分类错误
编辑模式下 status 不在 STATUS 枚举 → 状态错误
返回是否全部通过

校验失败：
    按 内容 → 分类 → 状态 的顺序
    聚焦第一个错误字段，停止提交

buildPatch()

changes ← 空对象
若 trim(内容) ≠ trim(初始内容)：
    changes.contact ← trim(内容)
若分类 ≠ 初始分类：
    changes.tag ← 当前分类
若状态 ≠ 初始状态：
    changes.status ← 当前状态
返回 changes
例如只把 CREATE 改成 DONE，PATCH 正文只有 {"status":"DONE"}。只改变内容首尾空白不算变更。编辑器负责比较新旧值，API 层再做可发送字段过滤。

关闭前的 hasChange()

新建模式：内容 trim 后非空，或分类与初始分类不同 → 有改动
编辑模式：内容 trim 后、分类、状态任意一项不同 → 有改动

无改动的编辑仍先经过校验；通过后直接关闭，并回调 unchanged: true，不写入、不刷新、不显示成功提示。

05提交：写入完成后，等待刷新

handleSubmit(event)：
    阻止表单默认提交
    若 submitting → 忽略重复提交
    若 validate 失败 → 聚焦错误字段，结束

    编辑模式：
        changes ← buildPatch()
        若为空：关闭，回调 unchanged，结束
        锁定表单
        等待 Store.update(item.ID, changes)
    新建模式：
        锁定表单
        等待 Store.create({ contact: trim(内容), tag, status: CREATE })

    成功 → 关闭弹窗 → onSaved(结果, mode)
    失败 → 解锁表单 → 展示错误并聚焦
锁定表单提交与取消禁用
内容只读，选择器禁用
→
POST / PATCH写入后端
→
refresh()沿用当前筛选
重新获取列表
→
关闭与反馈回调 onSaved
显示成功 Toast

写入失败

Store 将写入错误抛给编辑器。弹窗保留输入，恢复按钮与控件，显示字段错误和整体错误，用户可以修改后重试。

写入成功，刷新失败

load 将刷新错误写入 state.error，不抛出。因此 Store 仍返回写入结果，编辑器关闭并显示成功提示；若当前列表仍挂载，会显示刷新错误和重试按钮。

成功提示是在 refresh 结束后触发，不是在写入响应刚返回时触发。刷新使用现有筛选，因此新建或改分类后的条目不一定出现在当前列表。

06关闭、错误恢复与焦点

用户取消 / Esc

点击取消 → requestClose()
按 Esc → 阻止 dialog 默认关闭 → requestClose()

requestClose()：
    正在提交 → 不关闭
    有未保存改动 → confirm 确认
        用户拒绝 → 保留弹窗
    调用 close()

close()：
    已关闭 → 不重复处理
    closed = true，active = null
    dialog.close()

收到 close 事件：
    移除 dialog
    尝试将焦点恢复到打开前的元素

错误呈现与清除

后端 fieldErrors：
    contact / tag / status 消息各自用「；」连接
    写入对应字段提示
    按 内容 → 分类 → 状态 顺序聚焦
    formError ← error.message 或默认文案

内容 input：清除内容错误与表单错误
分类 change：只清除分类错误
状态 change：只清除状态错误
再次提交：先清空所有旧错误
返回的 close() 是直接关闭入口，不经过提交中检查或丢弃确认。用户点击取消和按 Esc 才走 requestClose()。焦点恢复是一次尝试；列表刷新可能已替换原卡片节点。

08底层状态与请求仍如何工作

Store 状态含义
items / loading / error列表数据、请求状态、失败时的 message 与 status。
filterstag 与 status，空字符串表示全部。
order默认 ORDER.NEWEST；ORDER.OLDEST 为最早优先。
hasLoaded有效请求成功或失败后置 true；当前页面不依赖它选择渲染分支。

加载与防止旧结果覆盖

load(overrides)：
    取消旧请求，创建新控制器
    seq ← ++requestSeq
    合并 filters，设置 loading，清空 error
    请求 itemApi.list
    成功且 seq 仍有效：排序后更新 items
    主动取消 / seq 过期：忽略
    其他失败：记录 error，结束 loading

cancelLoad()：
    增加序号，使旧结果失效
    取消请求并清空控制器引用
    loading = false

状态读取与发布

subscribe(listener)：加入集合，立即通知
setState(patch)：浅合并状态，通知订阅者
getState()：返回当前状态对象本身

setFilters → 重新请求
setOrder → 复制 items，按 time 字符串排序
refresh → 沿用 filters 重新请求
create / update / remove → 写入后 refresh

getState 不是不可变快照。当前编辑入口只从中查找条目，不直接修改对象。

条目 API映射与约束
list / getGET /items，非空 tag/status 放入查询参数；GET /items/{ID}。
createPOST /items；发送 contact、tag 和可选 status，不发送 ID/time。
patchPATCH /items/{ID}；只保留 contact/tag/status 的非 null、非 undefined 值；过滤后为空则本地报 400。
removeDELETE /items/{ID}；204 返回 null，当前没有界面按钮触发。
HTTP request：
    拼 URL，按需序列化 JSON 并设置 Content-Type
    合并外部取消信号与超时信号 → fetch
    204 / 成功空正文 → null
    成功正文 → JSON.parse
    失败响应 → 读取 detail → ApiError
        detail 数组：按 loc 汇总 fieldErrors 与 message
        detail 字符串：直接作为 message
        无可用 detail：按状态码提供默认文案
    捕获错误优先级：
        外部取消 → CanceledError
        超时 → ApiError(status = 0)
        已有 ApiError → 原样抛出
        其他 → 网络错误
    finally：清计时器与信号监听

计时器覆盖响应正文读取。写入错误原样到达编辑器，可显示 fieldErrors；列表加载仅将 message/status 保存到 state.error。

09配置、样式与阅读边界

配置当前值 / 行为
API_BASEhttp://127.0.0.1:8001；直接请求后端，跨源时需要后端允许前端来源。
REQUEST_TIMEOUT10000 毫秒。
ORDERNEWEST: newest；OLDEST: oldest，已修正旧拼写。
TAGTODOLIST → 待办；IMAGINATION → 想法。
STATUSCREATE → 待开始；RUNNING → 进行中；DONE → 已完成；CANCEL → 已取消；FAILED → 已失败。
当前样式items-dream.css：浅色列表与首页、窄屏布局、减少动态效果支持。
备用样式items.css：深色主题，当前 HTML 未加载。
  • 编辑器没有单独主题规则：现有两份 CSS 没有 editor 或 toast 专用选择器；dialog 主要呈现浏览器默认外观。本文的排版属于文档自身。
  • 编辑基于列表缓存：打开弹窗不请求最新单条数据，没有并发版本冲突检测。
  • 切页清理针对列表：弹窗在 body 下，未纳入 app 的列表清理函数；写入请求也不由 cancelLoad 取消。
  • 保存后的筛选仍有效：改分类或状态后，条目可能退出当前筛选结果；这不代表保存失败。
  • 没有前端持久化：筛选、排序和列表状态在内存中；草稿没有自动保存，页面刷新不会恢复。
  • 支持与预留分开：新建、编辑和列表已连接；独立详情、删除入口、分页尚未实现。
推荐沿一条路径阅读：app.openEditEditor → itemEditor.handleSubmit → itemStore.update → api.patch → http.request → itemStore.refresh → onSaved → toast。
