文件职责

js/app.js首页渲染、按路由挂载列表、保存并执行旧页面清理函数；编辑器与详情回调仍为占位。

js/state/itemStore.js持有列表状态、通知订阅者、取消旧请求、防止过期结果覆盖、串联写入与刷新。
js/api/items.js封装 list / get / create / patch / remove，不操作 DOM 或持有页面状态。
js/api/http.jsURL 拼接、JSON 请求、响应解析、取消、超时、统一接口错误。
js/constant.js / js/config.js路由、枚举、文案与默认参数。config.js 已通过请求层和 Store 参与运行。
目前已接入真实列表读取、筛选和排序。写入封装已经存在，但尚未连接到编辑表单；点击列表中的添加按钮或卡片，目前只在控制台输出占位消息。

03列表页：骨架固定，内容随状态更新

        非固定分类页面 → 分类下拉框

04状态层：加载、订阅与排序

现有状态字段初始值用途
items[]当前列表数据
loadingfalse是否正在加载
errornull失败时保存 message 与 status
filters{ tag: "", status: "" }当前请求筛选条件
orderDEFAULT_ORDER本地显示顺序
hasLoadedfalse当前有效请求成功或失败后置 true

订阅与通知

subscribe(listener)：
    将 listener 加入 Set
    立即调用 listener(state)
    返回从 Set 删除 listener 的函数

setState(patch)：
    state ← 浅合并旧 state 与 patch
    遍历订阅者快照，逐个通知

本地排序

sortItems(items, order)：
    复制数组，不原地改变传入数组
    取每项的 time 字符串，缺失时用空串
    比较字符串大小
    OLDSET → 升序，最早优先
    其他值 → 降序，最新优先

setOrder(order)：
    与当前值相同则结束
    否则更新 order 和排序后的 items
    不发起网络请求

load(overrides) 的完整逻辑

取消上一个请求，创建新的 AbortController
seq ← ++requestSeq
nextFilters ← 用显式提供的字段覆盖当前筛选
    未提供 → 沿用旧值；空字符串 → 全部
通知：loading = true，error = null，filters = nextFilters

尝试调用 itemApi.list(nextFilters, signal)：
    若 seq 已过期：结束，不修改状态
    通知：items = 按当前 order 排序后的结果
          loading = false，error = null，hasLoaded = true
失败时：
    若为主动取消或 seq 已过期：直接结束
    否则通知：loading = false，hasLoaded = true
              error = { message, status }

refresh() 调用无覆盖参数的 load()；setFilters() 合并筛选后调用 load()。普通加载失败写入状态，不向页面抛出。旧 items 保留在状态中，但被加载或错误视图遮住。

05快速切换时：取消 + 请求序号

取消请求用于停止无用的网络工作；请求序号用于防止旧结果覆盖新状态。即使旧请求仍然返回，也必须通过序号检查才能更新列表。

请求 Aseq = 1
筛选 TODOLIST
→
请求 B 开始取消 A；seq = 2
筛选 IMAGINATION
→
B 返回2 = 当前序号
接收并渲染
→
A 晚到1 ≠ 当前序号
丢弃结果

离开页面

列表页返回的清理函数：
    unsubscribe() 取消页面订阅
    cancelLoad() 取消列表请求
    移除 click / keydown / change 监听
    清空挂载点

cancelLoad()：
    ++requestSeq，使旧响应失效
    abort 当前控制器
    控制器引用 ← null
    通知 loading = false

为何先取消订阅？

cancelLoad 会更新状态并通知订阅者。先取消旧页面订阅，可以避免清理过程中又渲染即将移除的页面。

这一步不清空 items、filters、order 或 error。进入新列表时重新发起加载，恢复正确的筛选与显示。

Store 是共享模块状态；当前应用按一次只挂载一个列表页使用它。

06条目 API：参数如何进入请求

函数请求参数处理
listGET /itemstag、status 非空才写入 URLSearchParams；转交 signal。
getGET /items/{ID}使用传入 ID；转交 signal。
createPOST /items发送 contact、tag；status 不是 undefined/null 时才包含。ID 与 time 不发送。
patchPATCH /items/{ID}仅保留 contact、tag、status，跳过 undefined/null 与其他字段。
removeDELETE /items/{ID}无请求正文；204 由 HTTP 层解析为 null。
patch 并不比较新旧值，也不会逐项报错拒绝额外字段：它实际是过滤字段。过滤后没有可发送内容时，返回被拒绝的 Promise，错误为 ApiError（status 400），不发网络请求。

Store 的写入封装

create / update / remove：
    等待对应条目 API 写入
    写入失败 → 抛给调用方，不刷新
    写入成功 → 等待 refresh()
    返回写入结果

刷新失败：load 已将错误写入 state.error
因此写入本身仍返回成功结果

这部分逻辑已实现，但当前 app.js 的 onAdd 和 onOpenItem 只输出控制台消息，尚未触发写入封装或单条详情读取。

07HTTP：请求、响应与错误归一化

request(method, path, options)：
    启动超时计时器
    合并外部 signal 与超时 signal
    拼接 URL：完整 http(s) 地址直接使用
              相对接口路径拼接 API_BASE
    若 body 存在：JSON 序列化并设置 Content-Type
    调用 fetch，使用合并后的 signal

    状态 204 → 返回 null
    非成功响应 → 读取错误 detail → 抛出 ApiError
    成功响应 → 读取文本
        空文本 → 返回 null
        JSON 有效 → 返回解析结果
        JSON 无效 → 抛出无法解析数据的 ApiError

    捕获错误，按优先级分类
    无论结果如何：清除计时器，移除 signal 监听
捕获请求或正文读取错误
↓
从上到下匹配第一个条件
① 外部 signal 已取消
CanceledError
页面切换或新请求替代，不显示失败
② 超时 signal 已取消
ApiError，status = 0
显示请求超时提示
③ 已是 ApiError
保留原错误
例如 HTTP 422 / 500 或解析失败
④ 其他错误
ApiError，status = 0
统一为网络错误提示

后端错误 detail 的转换

detail 是数组：
    从 loc 移除 body / query / path
    剩余位置用点连接为字段名；空则为 _
    按字段汇总 msg → fieldErrors
    拼接可读文本 → message

detail 是非空字符串：直接作为 message
否则：使用状态码对应的默认提示

错误对象如何向上传递

ApiError 保留 message、status、fieldErrors、cause，并设置名称。CanceledError 单独表示主动取消。

列表 Store 仅把 message 和 status 放入 state.error；fieldErrors 留在原始接口错误中，供直接捕获写入错误的调用方使用。

超时计时器覆盖 fetch 与响应正文读取，最后才释放。默认上限为 10000 毫秒。

08配置、常量与当前边界

配置 / 常量值与用途
API_BASEhttp://127.0.0.1:8001；列表请求最终为该地址下的 /items，可附查询参数。
REQUEST_TIMEOUT10000 毫秒。
DEFAULT_ORDER / ORDER默认 ORDER.NEWSET；NEWSET: newset 为最新优先，OLDSET: oldset 为最早优先。保留现有拼写。
TAG / TAG_LABELSTODOLIST → 待办，IMAGINATION → 想法。
STATUS / STATUS_LABELSCREATE → 待开始；RUNNING → 进行中；DONE → 已完成；CANCEL → 已取消；FAILED → 已失败。
TAG_ALL / STATUS_ALL空字符串；页面与 Store 当前直接使用空字符串表示全部。
ROUTES / NAV_ITEMS四个页面配置与首页三个导航入口。Object.freeze 为浅冻结。
  • 样式尚未接入：css、js/components、js/utils 目录仍为空，index.html 未加载样式表；本说明页的样式只服务于文档阅读。
  • 读取已接入，编辑与详情待实现：首页按钮仍弹出建设中提示；列表添加与卡片点击只调用控制台占位回调。
  • 运行依赖：前端通过 HTTP 静态服务访问，后端在配置地址可用；跨源访问需后端允许前端来源。
  • 筛选与排序分工：tag/status 发给后端筛选，order 只在前端按 time 字符串排序，没有分页逻辑。
  • 没有持久化前端状态：当前列表和筛选只在模块内存中，刷新浏览器后重新初始化。
  • 共享状态按单页使用：切页取消的是列表请求，写入封装没有接入页面级取消；本阶段并无写入界面触发它们。
