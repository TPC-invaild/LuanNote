CODE READING / 后端阅读指南

从一次请求，理解后端

LuanNote 使用 FastAPI 接收条目操作，以 Pydantic 校验数据，通过内存字典和本地 JSON 文件保存待办事项与想法。

依据当前 backend 代码整理 · 2026-10-13 · 伪代码用于解释逻辑，非可执行代码 · 本页可离线阅读

01整体结构

项目将请求处理、数据约束与文件存储分成三层。读取通常使用缓存；创建、修改和删除先写入磁盘，再更新缓存。

客户端HTTP 请求
→
FastAPI 路由解析与校验输入
→
ItemStore查询或构建新数据
→
缓存 / JSON读取与持久化
文件职责
backend/main.py创建应用，启动时加载数据，挂载条目路由，提供根路径响应。
backend/Models/ItemModel.py定义完整条目 Item 的字段、默认值和校验规则。
backend/routers/items.py定义创建与更新请求模型，将 HTTP 请求转换为存储操作。
backend/Store/ItemStore.py管理缓存、线程锁、CRUD、文件读取和保存。
backend/share/dataPath.json指定主数据、临时数据和备份文件的相对路径。

02启动与首次加载

应用生命周期

导入存储模块：
    从当前源码位置确定项目根目录
    读取 dataPath.json，解析三个文件路径
    建立可重入锁 RLock
    缓存 ← 未加载（None）

创建 FastAPI 应用，挂载 /items 路由

启动时：
    调用 load()
    开始处理请求

关闭时：
    没有额外的保存或清理步骤

load() 的决策流程

进入线程锁
↓
缓存是否为 None？
否 ↓
直接返回已有缓存
是 ↓
读取磁盘
不存在 → 空字典
存在 → JSON 解析与 Item 校验
按 ID 建立字典，写入缓存并返回

离开 load() 时释放锁；后续读取复用缓存。

“未加载”的 None 与“已加载但无条目”的 {} 不同。空字典也会被缓存，不会因此反复读取磁盘。

03数据模型与校验

完整条目只有以下五个字段。字段名 contact 用于条目内容；标识符使用大写 ID。

字段类型规则与来源
time字符串默认是本地当前时间的 ISO 格式，精确到秒、不含时区；更新时保留原值。
contact字符串去除首尾空白后至少一个字符。
status枚举字符串CREATE、CANCEL、FAILED、DONE、RUNNING。创建请求默认 CREATE；完整 Item 模型本身无此默认值。
tag枚举字符串TODOLIST 或 IMAGINATION；创建时必填。
ID整数默认使用 time_ns() ÷ 1000 的整数部分；创建时若与已有键冲突，改用当前最大 ID + 1。

创建请求 · ItemCreat

接收 contact、status、tag。未提供 status 时填入 CREATE。

使用 Pydantic 默认额外字段策略：多余字段被忽略。因此请求中的 ID、time 不会传入存储层。

更新请求 · ItemPatch

三个业务字段均可省略，仅传入的字段参与更新；禁止额外字段。

省略 ≠ null：显式传入 null 返回 422；空对象返回 400；不能通过此接口修改 ID 或 time。

Item 禁止额外字段，去除字符串首尾空白，并启用 frozen 与 from_attributes。更新不会直接修改旧对象，而是合并字段后创建一个新的 Item。状态仅校验枚举值，没有规定状态转换顺序。

04接口一览

方法与路径行为成功结果
GET /基础响应200 · {"message":"hello world!"}
GET /items可按 status、tag 查询参数筛选200 · Item 数组，按 time 升序
GET /items/{item_id}按整数 ID 查询单条200 · Item
POST /items创建条目201 · 新 Item
PATCH /items/{item_id}局部更新条目200 · 更新后的 Item
DELETE /items/{item_id}删除条目204 · 无响应正文

查询、更新、删除的目标不存在时返回 404。请求模型或路径整数校验失败时返回 422。列表过滤参数目前是普通字符串：空字符串不筛选，不匹配的值返回空列表。FastAPI 默认提供 /docs、/redoc 和 /openapi.json。

05增删改查：逐步展开

读取 · list_items / get_item

查询列表(status, tag)：
    条目集合 ← load() 的所有值
    若 status 非空：保留状态相等的条目
    若 tag 非空：保留分类相等的条目
    按 time 升序排序并返回

查询单条(ID)：
    条目 ← load().get(ID)
    若不存在：路由返回 404
    否则：路由返回条目

创建 · creat_item

路由校验创建请求并转为字典

进入线程锁：
    新字典 ← 复制 load() 的结果
    新条目 ← Item(请求字段)
    若新 ID 已存在：
        用「最大 ID + 1」重新构建条目
    新字典[新条目.ID] ← 新条目
    save(新字典)
    返回新条目

路由返回 201

更新 · update_item

路由只提取显式提供的字段
若没有字段：返回 400
若任一字段为 null：返回 422

进入线程锁：
    新字典 ← 复制 load() 的结果
    旧条目 ← 新字典.get(ID)
    若不存在：返回 None → 路由返回 404
    合并数据 ← 旧字段 + 更新字段
    强制保留原 ID 和 time
    新条目 ← Item(合并数据)，重新校验
    新字典[ID] ← 新条目
    save(新字典)
    返回新条目 → 路由返回 200

删除 · delete_item

进入线程锁：
    新字典 ← 复制 load() 的结果
    若 ID 不存在：
        返回 False → 路由返回 404
    从新字典移除 ID
    save(新字典)
    返回 True

路由返回 204，无正文

修改操作复制字典后再保存。旧 Item 不会原地修改，缓存也不会在磁盘保存成功前替换。

局部更新的分支流程

PATCH 请求 → 请求模型校验
↓
输入是否有效？
否 ↓
无更新字段 → 400
非法值 / 额外字段 / null → 422
是 ↓
按 ID 查找条目
不存在 → 404
存在 → 合并并重新校验 → 保存 → 200

06保存、备份与缓存

内存中保存 {ID: Item} 字典；磁盘中保存由条目对象组成的 JSON 数组。配置路径均相对于项目根目录。

配置键文件用途
DATAdatabase/item.json当前持久化数据
TMPdatabase/item.json.tmp即将写入的新版本
BAKdatabase/item.json.bak覆盖主文件前复制的旧版本
序列化Item → JSON 数组
→
写入 TMPUTF-8，保留中文
→
备份旧 DATA存在时复制到 BAK
→
替换 DATAos.replace(TMP, DATA)
→
更新缓存指向新字典
save(新字典)：
    进入可重入锁：
        数据数组 ← 逐个 Item 转为 JSON 可序列化对象
        将数据数组写入 TMP（缩进 2，中文不转义）
        若 DATA 存在：复制 DATA 到 BAK
        用 TMP 替换 DATA
        缓存 ← 新字典
CRUD、load() 和 save() 都可能进入同一把锁，所以使用允许同一线程重复获取的 RLock。锁保护单进程内的操作；主文件替换是保存流程的最后一个磁盘步骤，缓存仅在该步骤成功后更新。

07阅读时需要知道的实现边界

  • 缓存不会自动刷新：首次加载后，手动修改磁盘文件不会立即反映到内存。
  • 线程锁不跨进程：多个服务进程拥有独立缓存，当前实现没有跨进程写入协调。
  • 备份不会自动恢复：代码会写入 BAK，但读取时仅使用 DATA；损坏 JSON、模型校验失败和磁盘错误会向上抛出，没有专门的恢复逻辑。
  • 目录需要已存在：保存逻辑不会创建 database 目录。主文件不存在时可从空数据开始。
  • 整份数据读写：创建、更新或删除都会重新写入整个 JSON 数组；没有分页或增量写入。
  • 时间是字符串：排序直接比较 time 字符串，当前模型没有对已有文件里的时间做日期格式校验。

这些是当前源码行为的说明，不代表本次新增了功能或更改了后端实现。
